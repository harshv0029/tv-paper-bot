What actually changes, and why

Research → Main

Upgrade from "writes strategy_log.xlsx, hope Main reads it" to Research Agent sending Main a message the moment a candidate crosses its own stated >50%-swept-combo logging bar.

Why: this session's own audit found Main's STRATEGY_LOG.md never once cross-referenced the xlsx — the file existed, the read didn't. Journal Sync already proves this exact pattern works.

Sentiment Agent → Main

Same upgrade: message Main directly when a sector read flags a specific, named stock — the case SENTIMENT_AGENT_BRIEF.md already describes as worth surfacing.

Why: docs/sentiment_log/ already holds three days of real per-symbol and sector reads that had no confirmed path back into a decision.

Deploy Gate → Main

Clarify the relay target as Main only, not an ambiguous "relays to the user" that could mean either.

Why: Main is the one holding full context on why a change was made — a status that reaches the user only through Main stays one source of truth instead of two possibly-inconsistent ones.

Sentiment Agent ··· Research Agent

Left unconnected on purpose, not fixed.

Why: SENTIMENT_AGENT_BRIEF.md calls a flagged stock "a research signal ... not an instruction to trade." Routing it through Main keeps Main as the one place the backtest-evidence bar actually gets applied, instead of Research quietly trusting an unvetted sentiment read. "Optimize" here means confirming the chokepoint is deliberate, not adding a shortcut around it.
